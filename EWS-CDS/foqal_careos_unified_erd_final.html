Foqal CareOS — Unified Database Architecture

Synthesised from three source architectures: current production schema, the integrated plan, and the professor's proposed ERD. Takes schema isolation from the integrated plan, billing / insurance / section-level summaries from the professor's ERD, and rich vital signs / MIMIC clinical data / AI accuracy tracking from the current production schema.

Design Principles Why This Structure
Key decisions made by synthesising all three source architectures. Each resolves a concrete problem identified in the comparison analysis.
🏗️

3-Schema PostgreSQL Isolation

hospital_core, ews, and discharge_ai are separate PG schemas in one Cloud SQL instance. Schema-level permission grants possible. Eliminates the prefix-based antipattern (app_*, ews_*, ap_*) of the current system. Adopted from the Integrated Plan.

🔑

admission_id UUID — Universal Key

Created in hospital_core.admissions, this UUID flows through every ews.* and discharge_ai.* table as the cross-schema join key. Replaces the MIMIC-specific hadm_id. The hadm_id field is kept as a compatibility column. Adopted from the Integrated Plan.

👤

Patient Identity ≠ Admission Episode

Current system conflates patient and admission in active_patients. Final design: patients (UHID, demographics) → many admissions (per-hospitalization UUID). Enables readmission tracking, insurance continuity, lifetime record. Adopted from Professor's ERD.

👩‍⚕️

STAFF Table with Nursing Roles

Current EWS tables store escalated_by, recorded_by as free-text strings — breaking NABH audit trails. Final design: hospital_core.staff with staff_id UUID, license_no, and 7 roles including staff_nurse and charge_nurse. All clinical events FK to staff_id. Adopted from the Integrated Plan.

📋

Per-Section NABH Discharge Tracking

Current app_summaries stores the entire summary as one TEXT blob. Final design adds discharge_sections (one row per NABH section with confidence_score and edited_by) plus discharge_amendments (rejection → regeneration workflow with version tracking). Adopted from Professor's ERD.

💊

Database-Driven Drug-Lab Rules

Current system stores 11 rules in YAML — correct for one hospital, unscalable for multi-hospital. Final design: drug_lab_rules table with hospital_id scope (NULL = global) and versioning. YAML remains the seed source; rules imported to DB on deploy. Adopted from Professor's ERD.

🫀

Rich Vitals Retained + recorded_by FK

Professor's patient_vitals had only 4 fields (spo2, rr, hr, bp). Final ews.vitals_timeseries keeps all 12 current production fields (temperature, AVPU consciousness, fluid_balance, weight_kg, air_or_oxygen, urine_output) and adds a recorded_by FK to staff for NABH attribution.

🔬

MIMIC-IV ap_* Tables Preserved

18 MIMIC-IV clinical tables (ap_labevents, ap_chartevents, ap_prescriptions, etc.) are the RAG knowledge base for the discharge summary AI. The professor's ERD had no equivalent. Kept as-is in discharge_ai schema, keyed on hadm_id with an admission_id bridge column.

🏥

Insurance + Billing Tables Added

Current schema has DRG/billing fields denormalized in active_patients with no computation tables. Final design adds insurance_policies, pre_auth_requests, cost_lookups, and billing — enabling Ayushman Bharat / CGHS pre-authorisation and cost estimation workflows. Adopted from Professor's ERD.

📊

AI Accuracy error_log Preserved

The 3-tier error logging framework (error_tier 1/2/3, per NABH section, source_present flag, rolling 7-day view) exists nowhere in the professor's design. Critical for monitoring hallucination rate and the NABH launch gate. Preserved from current production schema.

Patient Journey: Admission to Discharge

          participant HIS as HIS Feed
          participant HC as hospital_core
          participant EWS as ews schema
          participant DAI as discharge_ai
          participant N as notifications

          HIS->>HC: ADT event
          HC->>HC: Create patients record with UHID
          HC->>HC: Create admissions record, generate admission_id UUID
          HC->>HC: Assign doctor via doctor_patient_assignments

          loop Every 4 hours
          EWS->>EWS: Insert vitals_timeseries 12 fields
          EWS->>EWS: Insert lab_events 10 biomarkers
          EWS->>EWS: Evaluate drug_lab_rules, create drug_lab_flags if triggered
          EWS->>EWS: Compute NEWS2, create escalations if threshold crossed
          EWS->>N: Insert notification type escalation_pending
          end

          EWS->>EWS: ML model produces ews_events STEP_DOWN_ELIGIBLE
          EWS->>EWS: Nurse creates transfer_requests with checklist
          EWS->>EWS: Charge nurse approves, attending signs
          HC->>HC: Log ward_transfers ADT entry CCU to GW
          HC->>HC: admissions.status = discharge_pending

          DAI->>DAI: Create active_patients linking hadm_id to admission_id
          DAI->>DAI: Fetch MIMIC or HIS data into ap_tables
          DAI->>DAI: Create app_encounters
          DAI->>DAI: Gemini plus RAG generates app_summaries
          DAI->>DAI: Split into discharge_sections 15 NABH sections
          DAI->>N: Insert notification type summary_ready

          DAI->>DAI: Doctor rejects sections, creates discharge_amendments
          DAI->>DAI: Regenerate new discharge_sections version
          DAI->>DAI: Doctor signs app_summaries

          DAI->>DAI: Create billing linked to cost_lookup and insurance_policy
          HC->>HC: pre_auth_requests to insurance provider
          HC->>HC: admissions.status = discharged
