Section 01

Problem Statement & Architecture Decision

Both projects currently operate as isolated systems with incompatible patient identity models, separate databases, and no shared data layer. The integration goal is to create a single shared Cloud SQL instance that ties both systems together through a common admission_id that travels with the patient from admission to discharge.

Gap Current State Target State
Patient Identity EWS uses integer subject_id; Discharge AI uses integer hadm_id — two unrelated keys Single UUID admission_id shared across both systems + UHID for master patient record
Database EWS: SQLite file on laptop. Discharge AI: Cloud SQL (separate) Single Google Cloud SQL PostgreSQL instance, 3 schemas, both apps connect to it
Staff / Doctors No staff table in EWS; Discharge AI has app_users (auth-only) Unified hospital_core.staff table — one record per clinical staff member across both apps
Doctor-Patient Mapping No doctor assigned to patient in EWS; no chain of custody doctor_patient_assignments tracks which consultant is responsible at every point — feeds Discharge AI sign-off
Ward Transfer Not tracked in EWS; no CCU→GW transition record Full ADT log in ward_transfers; beds, wards, and admissions auto-updated on transfer completion
Escalation Hierarchy No defined approval chain — single escalation table, no co-sign Nurse → Head Nurse (gatekeeper/false-alarm screening) → Attending. Head Nurse is mandatory tier for levels 1–2.
Multi-Hospital No hospital_id — impossible to scale to multiple sites hospital_id UUID on every master record; UHID format includes hospital short_code

Section 05

End-to-End Data Flow — Admission to Discharge

ADMISSION

Patient Registration & Admission

  • hospital_core Admin Staff registers: patients row created with UHID (e.g. AIIMS-2026-0001234)
  • hospital_core Admission event: admissions row created → generates admission_id UUID
  • hospital_core Treating Consultant assigned → doctor_patient_assignments row (type=PRIMARY)
  • hospital_core CCU bed assigned → beds.status = 'occupied', beds.current_admission_id = admission_id
CCU MONITORING

EWS Monitoring Loop (every hour)

  • ews Nurse enters vitals → vitals_timeseries row (keyed by admission_id)
  • ews NEWS2 score computed + EWMA trend engine runs → ews_events if threshold crossed
  • ews Labs entered → lab_events; Drug-lab YAML rules evaluated → alerts on ews_events
  • ews DCM patients: fluid balance entered → fluid_balance; weight gain alerts → ews_events
  • ews If NEWS2 ≥ 5 → nurse creates escalations row → Head Nurse gatekeeper flow (Section 06)
CCU → GW TRANSFER

Step-Down / De-escalation

  • ews System detects: NEWS2 ≤ 2 sustained 6h+ → ews_events.event_type = 'STEP_DOWN_ELIGIBLE'
  • ews Staff Nurse fills N_transfer form → transfer_requests row (status: pending_charge)
  • ews Head Nurse approves in N5 → status: approved; Attending notified (no sign required)
  • hospital_core ward_transfers row created (CCU→GW); admissions.current_ward_id updated; beds updated
  • ews Patient disappears from N1 (CCU dashboard) → appears on G1 (GW dashboard)
GW MONITORING

General Ward — Lower Intensity

  • ews Vitals q2h (vs q1h in CCU) → same vitals_timeseries table, different ward context
  • ews GW escalation: Nurse → Ward Doctor → Attending (if deterioration → GW→CCU readmission)
  • ews Discharge readiness: NEWS2 ≤ 1, stable, attending approval → "Flag for Discharge" button
DISCHARGE HANDOFF

EWS → Discharge AI Handoff

  • ews Attending approves discharge → Foqal CareOS backend fires POST to Discharge AI with admission_id
  • discharge_ai active_patients + app_encounters rows created. Status: Pending_Ingestion
  • discharge_ai BigQuery ETL / CSV upload populates ap_* clinical tables for this admission
  • discharge_ai Gemini 2.5 Flash two-pass pipeline generates 10-section NABH discharge summary
  • discharge_ai Consultant reviews and signs → app_summaries.signed_by = staff_id from doctor_patient_assignments
DISCHARGE COMPLETE

Close of Admission

  • hospital_core admissions.status = 'discharged', discharged_at = now()
  • hospital_core beds.status = 'available', beds.current_admission_id = NULL
  • hospital_core doctor_patient_assignments.unassigned_at = now() for PRIMARY assignment

Design Principles (Production Grade)

UUID Primary Keys Everywhere

No integer PKs except MIMIC-IV legacy. UUIDs prevent collisions across hospitals when scaling to multi-site deployment.

Audit Trail — Insert Only

Clinical data is never UPDATE'd — each correction appends a new row. Vitals, labs, escalations are immutable once written.

NABH Compliance

Every escalation has documented response timestamps. All clinical sign-offs stored with timestamp + staff_id. SLA breaches auto-flagged.

Chain of Custody

doctor_patient_assignments ensures every clinical action maps to the doctor responsible at that moment in time.

Admission ID is the Universal Key

Never pass patient name or UHID between systems. Always use admission_id (UUID). Both Sabari and Ashmit keyed to this single value.

Ward Type Gates

CCU patients only visible in CCU screens (N1); GW patients only in GW screens (G1). Transfer is the explicit, audited boundary crossing.

Soft Deletes

is_active = FALSE instead of DELETE for staff and patients. Clinical records are never physically deleted.

Hot-Reloadable Rules

Drug-lab interaction rules remain in YAML (drug_lab_rules.yaml). New rules added without Python code changes or server restart.
