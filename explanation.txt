Reading order

Phase 1 — Orientation (~30 min)

1. README.md — you've got context, but re-read section "Repository Structure"
2. deploy.sh — the single source of truth for what actually runs. 5 processes, 5 ports.
3. frontend/config.js:1-21 — 21 lines, shows how the frontends find the backends
4. backend/cloud_sql_schema.sql + backend/app/migrations/ (read 001 → 027 in numeric order) — this is the best way to learn the data model. Each migration is small and tells you why a feature exists.

Phase 2 — The data layer (this is the foundation)

5. backend/app/cloud_sql_db.py (105 lines) — connection/engine setup
6. backend/app/data_server.py:1-11 — read the docstring first, it explains the cache-aside pattern
7. backend/app/cloud_sql_reader.py (258) — reads ap_* cached tables
8. backend/app/bq_mimic_loader.py (604) — BigQuery → MIMIC-IV pulls
9. backend/app/bigquery_mimic_loader.py (656) — the fetch-and-store ETL
10. backend/app/data_server.py (full, 953) — now it'll make sense
11. backend/app/cloud_sql_app_db.py (1117) — app-level tables (encounters, summaries, users, audit). Heavily used by main.py.
